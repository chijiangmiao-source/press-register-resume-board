# 四色套准复测接力板

印刷机调校过程中，平板可能被误刷新。本应用是一个**只在浏览器运行**的四色套准复测接力板：
TypeScript + Vue 3 + Vite，无业务后端、不访问任何在线服务。一次会话的进度以检查点形式
原子写入 `localStorage`，刷新、关闭后重开都停在同一步，避免漏检色版或重复采用旧读数。

## 测量规则

- 一次会话固定依次测量 **青版、品红版**（黑版为基准），每版按
  **左上 → 右上 → 右下 → 左下** 提交，共八步，顺序不可调整。
- **开始新会话时选择录入单位：毫米（mm）或微米（µm）**，选定后随会话锁定，
  进行中的会话不可中途更改，避免同一批读数被两种单位误读：
  - 毫米：范围 **−2.00 ~ +2.00 mm**，精确到 **0.01 mm**；
  - 微米：范围 **−2000 ~ +2000 µm**，按 **10 µm** 步进（恰为 0.01 mm），
    由单位层校验后换算成毫米；
  - **两个值都合法才推进**；任一非法则行内报错，不前进、不写检查点。
- 存储与计算始终只以 **0.01 mm** 精度进行；历史读数、超差清单与校正建议
  按会话锁定单位一致显示，且不会出现 `-0` 负零。
- **已提交步骤不可回改；唯一例外是录入阶段的“撤回上一步”**：
  测量页仅在已有提交且尚未完成时显示撤回入口，按钮与确认框都标明将回到的
  色版与角点；确认后删除末条读数、回退 `nextIndex`，并用**一次** `setItem`
  原子替换检查点，会话编号与锁定单位保持不变。取消确认或检查点写入失败都
  保留原进度（写入失败会给出明确反馈，可重试）。撤回后重新提交仍经过既有
  范围与精度校验，放行结论与逐版诊断只基于新的八步数据生成；完成页不提供
  撤回入口。该能力不改动检查点结构（仍为 v2），旧有效检查点无需迁移。
- 每次推进后，会话编号、**录入单位**、八步定义、已提交值与**独立保存的下一步索引 `nextIndex`**
  通过**一次** `setItem` 原子写入 `localStorage`（键：`registration-relay-board:session`，
  当前结构版本 v2）。进度直接读取 `nextIndex`，不按已提交读数数量反推；
  恢复时还会校验 `nextIndex === values.length`，不一致即判定记录损坏。
  恢复时校验 `unit` 取值（仅 `mm` / `um`）；**未含该字段的旧有效记录按毫米载入**，
  版本号保持不变。
- 八步完成后：
  - 所有 |X|、|Y| 均 **≤ 0.15 mm** → 显示 **“可开印”**；
  - 否则显示 **“需复调”**，并按测量顺序列出全部超差色版、角点及超差轴偏移。
- “需复调”下还会**逐色版给出校正建议**（基于既有只读测量值现场计算，不落盘）：
  - 分别对青版、品红版计算四个角点的 **X、Y 平均偏移**及各角点相对均值的**残差**；
  - 残差绝对值**均不超过 0.05 mm**（恰好 0.05 mm 也归入此类）→ 判为
    **整版平移**，按 **0.01 mm** 给出与平均偏移**方向相反**的 X、Y 建议量
    （半厘按远离零方向取整，绝不出现 `-0.00` 负零）；
  - 任一残差越界 → 显示 **“角点不一致，需逐角复测”**，**不输出**任何可能误导的调整量。
- 诊断只是八步完成后的**只读派生结果**：不向检查点增加字段、不改变存储版本（仍为 v2），
  未完成会话、刷新续作与旧检查点结构的行为完全不变。
- **新会话必须经确认后才会清除旧检查点**。
- 进行中的会话与完成页都有重开入口：返回起始页可重新选择录入单位，
  确认后才清除旧检查点；**取消确认则回到原会话视图**（录入页或完成结果），
  不会把调机员留在起始页。
- 本地记录损坏、版本不匹配或读数精度不足 0.01 mm 时**明确报错并阻断续作**，
  提供重置入口，绝不猜测进度。

## 本地开发

```bash
npm install
npm run dev        # http://localhost:5173
```

## 测试

```bash
npm run typecheck  # vue-tsc 类型检查
npm run test       # Vitest：状态迁移 / 恢复 / 非法推进拒绝 / 结论判定
npx playwright install chromium   # 首次需要下载浏览器
npm run e2e        # Playwright：含“中途刷新续作”“损坏记录阻断”等
npm run verify     # 串行执行上述全部验收
```

关键用例：

- `src/registration/store.test.ts` — 八步推进、原子写入、刷新恢复、
  非法/越界/精度不足拒绝、完成后锁定、损坏与版本不匹配阻断、放行与超差清单顺序、
  复调诊断只在完成后生成且不改变检查点结构；
  微米会话的步进校验、毫米换算落盘、单位随检查点恢复、旧记录缺省按毫米载入、
  非法单位取值阻断；撤回最近提交的末条删除、索引回退、单次原子落盘、
  首步前/完成后拒绝撤回、写入失败不改内存与落盘状态。
- `src/registration/units.test.ts` — 两种单位的边界（±2.00 mm / ±2000 µm）、
  步进（0.01 mm / 10 µm）、微米↔毫米换算、单位化展示与负零防护。
- `src/registration/diagnosis.test.ts` — 整版平移 / 角点不一致两类诊断、
  残差 0.05 mm 边界（归入平移）、半厘舍入与负零防护、未完成拒绝诊断。
- `e2e/relay.spec.ts` — 真实浏览器中提交两步后 `reload()`，校验停在第 3 步、
  旧读数保留、会话编号不变，续作完成后得到“需复调”及按序超差清单；
  另有从正常录入走到“需复调”，确认逐版校正建议随对应色版展示；
  进行中的会话可从重开入口返回起始页重新选单位，取消清除确认回到原会话视图；
  读数精度不足 0.01 mm 的检查点判为损坏并阻断续作。
- `e2e/unit.spec.ts` — 从选择微米开始，非法微米输入行内报错且不写盘，
  提交若干步后刷新续作至完成，全程单位展示统一（无毫米混入、无负零），
  放行结论与诊断数值和毫米用例等价；另覆盖旧记录按毫米载入与非法单位阻断。
- `e2e/undo.spec.ts` — 录入三步后撤回第三步：确认框标明将回到的色版角点，
  取消确认保留原进度；确认撤回后历史行移除、回到第三步且会话编号与单位不变，
  刷新仍停在第三步；重新提交仍经范围校验，完成八步后结论只基于新数据；
  首步前与完成后均无撤回入口。

## Docker Compose

```bash
# 构建并启动 Web（宿主端口默认 8080，可用 WEB_PORT 覆盖）
WEB_PORT=9000 docker compose up --build web

# 一次性验收服务：类型检查 + Vitest + Playwright（访问 compose 内的 web 服务）
docker compose run --rm verify
```

- `web`：使用 `vite preview` 托管纯静态产物，容器内固定监听 4173；
  宿主端口由 `WEB_PORT`（默认 `8080`）控制。
- `verify`：一次性服务，结束即退出，退出码代表验收结果。
